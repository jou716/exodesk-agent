# U12 客户级跨工单记忆

## 目标

在不扩大当前工单上下文的前提下，让同一客户的新工单能够读取此前工单的关键背景，同时保证不同客户之间严格隔离。

## 实现

- `ConversationMemory` 升级为三层记忆：会话最近消息、工单内摘要、客户历史工单摘要。
- 客户身份优先使用 `Ticket.customer_id`；仅当工单尚未绑定客户时，才按唯一邮箱回退。
- 默认读取同一客户最近 3 个其他工单，提取状态、主题、设备型号、质保状态、最近消息和会话摘要。
- 跨工单摘要默认最多 1800 字符，且不超过总上下文预算的三分之一。
- 当前工单被显式排除，历史内容标注为背景信息，不覆盖当前客户消息。
- `load_context` 日志展示命中的历史工单 ID、摘要字符数和摘要预览。
- 工具规划和回复生成提示词均注入 `CUSTOMER_MEMORY`，并附带“仅作背景、当前会话优先”的约束。
- 种子数据新增 `T-2399`，演示 Emma Walker 在 `T-2401` 前已解决的一次膝部绑带问题。

## 验收

- [x] 同客户新工单能读取历史工单的设备与处理结论。
- [x] 不同客户之间不能互相读取工单内容。
- [x] 当前工单不会重复进入客户历史摘要。
- [x] 历史摘要超过预算时自动裁剪。
- [x] 客户级记忆进入工具规划与最终回复提示词。
- [x] 原有工单内跨会话记忆保持通过。
